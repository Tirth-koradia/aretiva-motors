### Interview Preparation: Key Architectural Rationale

When explaining the design decisions in your interview, emphasize:

1. **PostgreSQL vs. NoSQL / Document Store:**
   - Relational schema guarantees referential integrity between vehicles, users, and transactions.
   - ACID transactions allow atomic conditional balance/stock updates with zero risk of negative quantities.
2. **Stateless JWT vs. Stateful Sessions:**
   - Decoupled React SPA and FastAPI backend communicate via standard Bearer tokens containing user identity and role claims (`sub`, `role`, `iss`, `aud`, `exp`).
3. **Server-Enforced Role-Based Access Control (RBAC):**
   - Hiding UI buttons is convenience, not security. FastAPI dependency injection (`require_role(UserRole.ADMIN)`) enforces role constraints on all mutation endpoints (`POST`, `PUT`, `DELETE`, restock, activity).
4. **Conditional Stock Updates for Concurrency:**
   - `UPDATE vehicles SET quantity = quantity - 1 WHERE id = :id AND quantity >= 1 RETURNING quantity`.
   - Prevents race conditions and overselling when multiple buyers attempt to purchase the final unit simultaneously without table-locking overhead.
5. **Append-Only Immutable Ledger (`InventoryTransaction`):**
   - Stock is never mutated in isolation; every restock and customer purchase creates an immutable transaction entry for accountability and auditability.
6. **Soft Deletion (`deleted_at`):**
   - Preserves historical purchase references while hiding removed inventory from active showroom visitors.
7. **Server-Side Pagination & Filtering:**
   - Preserves database index usage on `make`, `category`, and `price` without downloading the full catalogue to the client.

        reason.message.includes('AbortSignal')
      )

  if (typeof window !== 'undefined') {
    window.addEventListener('unhandledrejection', (event) => {
      if (isAbortError(event.reason)) event.preventDefault()
    })
  }

  if (typeof process !== 'undefined' && typeof process.on === 'function') {
    process.on('unhandledRejection', (reason) => {
      if (isAbortError(reason)) return
    })

### What Caused "Failed to fetch"

In modern browsers, `TypeError: Failed to fetch` occurs when a network request fails before receiving an HTTP response. In our setup, this was caused by two environment factors:

1. **Vercel API Route Rewriting (Production):**
   - In [`frontend/vercel.json`](file:///Users/koradiatirth/Desktop/incubyte/frontend/vercel.json), all routes were previously matching `/(.*)` and redirecting to static `/index.html`.
   - When calling `POST /api/vehicles` on the deployed frontend, Vercel attempted to send the `POST` payload to a static HTML document rather than proxying it to the backend on Render, triggering a browser network fetch failure.

2. **IPv6 Connection Fallback on macOS (Local Dev):**
   - In [`frontend/vite.config.ts`](file:///Users/koradiatirth/Desktop/incubyte/frontend/vite.config.ts), Vite's dev proxy target was set to `http://localhost:8000`.
   - On macOS with Node 18+, Node resolves `localhost` to IPv6 `::1` first. When uvicorn listens on IPv4 (`0.0.0.0`), the IPv6 attempt timed out or dropped the socket before falling back to IPv4, resulting in a browser gateway failure.

3. **Backend Cold-Starts (Render Free Tier):**
   - Render's free tier spins down idle instances after 15 minutes of inactivity. When awoken, the first request takes ~15–30 seconds while the container boots, which can exceed default browser request timeouts.

---

### What Was Fixed

1. **Vercel API Edge Proxy Rewrites ([`frontend/vercel.json`](file:///Users/koradiatirth/Desktop/incubyte/frontend/vercel.json)):**

     ```json
     {
       "source": "/api/(.*)",
       "destination": "https://aretiva-backend.onrender.com/api/$1"
     }
     ```
   - This ensures all requests from Vercel reach the Render backend seamlessly with zero CORS issues.

2. **Local Dev Proxy IPv4 Target ([`frontend/vite.config.ts`](file:///Users/koradiatirth/Desktop/incubyte/frontend/vite.config.ts)):**
   - Updated the default proxy target from `http://localhost:8000` to `http://127.0.0.1:8000`, eliminating IPv6 DNS lookup delays and connection drops on macOS.

### Root Cause of the Error

Looking closely at your screenshot, the error occurred because the VIN entered was:
**`JTHHZ5EC2P5019284`**

In automotive databases, **VINs must be globally unique**. `JTHHZ5EC2P5019284` is the VIN of the **Lexus LC 500 Convertible** that is already seeded in the catalog.

#### Why did it say *"Network connection error"* instead of *"Duplicate VIN"*?
1. When a duplicate VIN was submitted, PostgreSQL raised a `UniqueViolation` database integrity error (`IntegrityError`).
2. Previously, the backend did not catch this database exception on vehicle creation, so FastAPI crashed with an unhandled `500 Internal Server Error`.
3. In browser web applications, unhandled 500 server crashes do not include CORS headers (`Access-Control-Allow-Origin`), causing the browser's `fetch()` call to abort with `TypeError: Failed to fetch`.
4. The frontend modal caught this network abort and displayed the generic *"Network connection error"* banner.

---

### What We Fixed & Improved

#### 1. Backend Domain Error & 409 Conflict Safeguard
- Added [`VehicleVinAlreadyExistsError`](file:///Users/koradiatirth/Desktop/incubyte/backend/src/aretiva/core/exceptions.py#L74-L82) (`HTTP 409 Conflict`).
- Updated [`create_vehicle`](file:///Users/koradiatirth/Desktop/incubyte/backend/src/aretiva/services/vehicles.py#L24-L35) and [`update_vehicle`](file:///Users/koradiatirth/Desktop/incubyte/backend/src/aretiva/services/vehicles.py#L65-L82) to catch database `IntegrityError`, roll back the session, and return a clear, structured JSON error with full CORS support:
  ```json
  {
    "error": {
      "code": "VEHICLE_VIN_ALREADY_EXISTS",
      "message": "A vehicle with this VIN already exists in the catalogue. Please use a unique 17-character VIN."
    }
  }
  ```
- Added automated integration test [`test_administrator_duplicate_vin_returns_409_conflict`](file:///Users/koradiatirth/Desktop/incubyte/backend/tests/integration/test_vehicle_creation.py#L85-L105) to ensure this is permanently verified.
